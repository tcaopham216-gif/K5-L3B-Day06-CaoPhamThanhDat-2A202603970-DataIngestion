# Implementation and reproducibility

The Python CLI ingests both raw Gutenberg sources, verifies the prewritten benchmark before importing embedding/store dependencies, indexes A/B with genuine FastEmbed vectors, and evaluates A/B/C on identical question vectors. C shares B's collection and applies only question-supplied metadata. All metrics and timings are computed at runtime. No fallback vectors or prefilled performance values exist.

Offsets are half-open Unicode character positions in each saved normalized book text. Source unit text excludes chapter headings (stored as metadata). Paragraph boundaries remain double newlines. Source units never cross chapters. Chapter-local terminal fragments merge backwards; a chapter shorter than 1500 characters is flagged. Blank separator runs are logged as empty paragraph slots, rather than treated as source content. Inline commentary and footnotes are retained. The Prince's appended Valentino account and Castruccio biography are excluded from the counted chapter range; the raw inclusive line range is calculated into the manifest.

Fixed windows end at source-unit boundaries. Paragraph chunking uses sentence boundaries for large paragraphs, retaining a single oversized sentence. A trailing fragment below 200 characters merges backwards even if the result exceeds the soft 1200-character target. Chunk offsets retain the exact source substring. Overlap can produce several candidates for a coherence position; the first chunk in deterministic order is sampled.

Chroma uses cosine HNSW approximate search. IDs are deterministic. Per-document upsert removes obsolete IDs before writing current chunks. Reload mode ingests again, asserts chunk text/metadata equality, reopens persisted collections, upserts the original real vectors for the identical inputs and checks counts against the expected chunk totals. C shares B and incurs no separate index build. Per-strategy query search times exclude the shared query embedding time, which is recorded separately. Model-load time is also separate.

The benchmark was authored before retrieval. Test chapters are disjoint from dev chapters, but thematic overlap and the same authors/translations limit independence. Book filters are scope supplied before retrieval, never derived from gold labels at search time. The four scoped questions concern warfare, deception and fortifications, which appear across both books. Exact normalized quote containment and gold source unit membership are both required for a hit. A retrieved gold page with an incomplete quote is flagged as possible evidence splitting; it can also reflect a different passage from the same unit. This diagnostic alone does not prove the quote was split at a boundary.

Audit CSV labels are populated, with means in starter/results/audit_summary.json. Coherence samples use AOW-p001..p005 and PRN-p001..p005 at unit start +300. Test audit covers every test question and top-three rank for every strategy. The labeler is AI: Claude Code orchestrating OpenAI Codex CLI assisted code, benchmark questions and manual audit labels. The student must review these labels; they are not independent human judgments and carry bias risk. Automated evidence hits and audit grounding are distinct measures.
